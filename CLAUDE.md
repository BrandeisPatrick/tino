# Working on tino

Read [JOURNAL.md](JOURNAL.md) first: its **Now** section holds the current state and what comes next. [docs/TRACKING.md](docs/TRACKING.md) says where everything lives. [docs/PHASE2.md](docs/PHASE2.md) holds the plan and the hypotheses written before any run.

## Keep the record

- Add a JOURNAL.md entry for every working day: what Patrick asked, what was done or decided and why, and what is next. Keep **Now** current.
- Nothing lives only on the Mac or in a chat. Write-ups go in this repo, weights and labels on the Hugging Face Hub. The run index, model registry, results file and timeline event log are generated by `uv run python scripts/collect_results.py`; commit them with each finished run.
- Commits and pull requests carry no attribution lines.
- Patrick runs every login himself (Hugging Face, Weights & Biases, GitHub). Never enter credentials.

## The machine: a 16 GB Apple M4 with unified memory

- Never risk freezing the Mac. Run one MLX job at a time, through the queue: `caffeinate -i nice -n 10 bash scripts/queue_run.sh`, with one job per line in `queue/pending.txt`. The file can be edited while a job runs. Before each job, the runner waits for 35% free memory and no Ollama model.
- Run nothing memory-heavy beside a running job, CPU work included, because the CPU and GPU share one pool. For checks, `touch queue/hold` and wait for the job boundary.
- `tino/guard.py` pauses a run under 25% free memory. It aborts under 12% free, on 6 GB of swap growth, or after 30 minutes paused. Do not loosen these limits to get a run through.
- Other apps that load local models (Ollama) caused past aborts. Ask before loading anything over 2 GB while the queue runs.

## Code and runs

- `scripts/train.py` and `scripts/train_gen.py` refuse to start from uncommitted code in `tino/`, `scripts/`, `configs/`, `pyproject.toml` or `uv.lock`. Commit first, or develop in a git worktree while a job runs.
- Run `--smoke` before any new long run.
- Phase 2 statistics: per-question correctness averaged over seeds, a paired sign-flip permutation test with a bootstrap interval, and Holm's correction within each research question. A difference counts as a claim only if every seed-matched pair agrees in sign; otherwise it is a lean.

## Clean up as you go

- After each finished run: regenerate the index, then delete `checkpoints/<id>/best` once its weights are byte-identical to `publish`. They differ only in the fitted temperature in `tino_config.json`; `publish` keeps it.
- Delete only what is regenerable or duplicated. Never delete weights that exist nowhere else.
- Resources that other projects or sessions own, such as Ollama models or their caches, need their owner's or Patrick's OK first.
