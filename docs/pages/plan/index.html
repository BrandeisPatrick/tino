Jev Decoder Experiment
Experiment plan · Oct 2026

Turning a small decoder into a Jev-style decision model

Three ways to teach Qwen3-class decoders to answer typed questions with calibrated probabilities, compared on one backbone, one dataset, and one 16 GB laptop. Every run leaves the machine.

1 · The target

What Jev does in one forward pass

TypeSafe's Jev takes a state plus typed questions and returns probabilities over options you supplied. No tokens are generated, so there is nothing to parse and nothing to hallucinate. The clone has to reproduce this contract exactly.

Input

state: "Customer asks for a refund
on a 40-day-old order. Policy
window is 30 days. Customer has
3 prior orders, no complaints."

questions:
  action:  choice [refund,
           escalate, decline]
  urgent:  noul "needs reply
           within 1 hour?"
  tone:    score 1..5
           (hostile → friendly)
→

Decision model

One pass. Zero tokens.

All questions are answered in parallel against the same encoded state. Output heads read option representations and emit a softmax, a sigmoid, or an expected level.

Jev: 70–500 ms, $0.042 / M input tokens
Target on M4: < 50 ms per question

Scale and calibrate

7 · Beyond the three methods

Ideas worth a run each

Does calibration survive distillation?
novel

Distill Jev's full distributions with KL, compare ECE against hard-label training. No open clone reports this.

Zero-training baseline
cheap

SemIf reads option probabilities from a frozen Qwen3.5-4B and already agrees with Jev 0.845 of the time. Fine-tuning has to beat this.

Head design ablation
ablation

Pointer head versus raw option logits versus option attention versus a plain classifier, same backbone and data.

Encoder versus decoder at matched size
ablation

ModernBERT-large (395M, as in Laya and Von) against Qwen3-0.6B. Tests whether a decoder is the right starting point at all.

Calibration-aware objectives
novel

Cross-entropy versus CE plus Brier score versus post-hoc temperature scaling. A cheap stand-in for what TypeSafe's RLCD claims to do.

Transfer to unseen sources
eval

Kev drops from in-distribution to new sources. Measure that gap per method; adapters and distillation should generalize differently.

Multi-question batching
eval

Jev answers many questions in one pass. Test whether several decide tokens in one forward pass cost accuracy.

Latency as a first-class metric
cheap

Report milliseconds per question on the M4 next to accuracy. Laya claims 33 ms on a T4; the student should land near that.

Your own environments as test beds
own projects

The TCG project gives a Choice question per turn. The agent harnesses give tool-call gating, Jev's headline use case.

Language retention
cheap

Perplexity after each method, to see whether one model can still generate text and decide.
