# How this repository is organized, and how everything is tracked

The rule: nothing about an experiment lives only on a laptop or in a chat. Every run, number, model, dataset revision, decision and lesson has a file here or a pinned revision on the Hub, and the conclusions are written down next to the evidence.

| Path | What it holds | Who writes it |

| [`LESSONS.md`](../LESSONS.md) | The nine lessons, each with its table | by hand |

## Where things live

| Thing | Where | How it is pinned |
|---|---|---|
| Code, configs, run records, write-ups | GitHub `BrandeisPatrick/tino` | every run's `provenance.json` records the commit it ran from; training refuses to start from uncommitted code |
| Model weights | private Hugging Face repos `BrandeisPatrick/tino-*` | `runs/<id>/checkpoint.json` records the repo and revision; `docs/MODELS.md` lists them |
| Training and evaluation data | `jaredpalmer/kev-suites` on the Hub | revision `cc4bac80` in `tino/data.py`; every file's SHA-256 is checked against the suite's manifest on load |
| Teacher labels | private dataset `BrandeisPatrick/tino-teacher-labels` | revision `31e5bfd7`; the manifest records the teacher, its revision, the prompt hash and the fitted temperature; student configs pin the revision |
| Training metrics while running | the run directory (always); Weights & Biases when the machine is logged in | `tino/track.py` |
| Per-question predictions | `runs/<id>/predictions/<suite>--<split>.jsonl.gz` | written at final evaluation; `scripts/eval_checkpoint.py` adds them to older runs and checks the accuracy still matches |

## A run directory

Run ids are `YYYYMMDD-HHMMSS-<name>`. Names follow the config name plus a suffix: `-s1` is seed 1, `-smoke` is a pipeline check on a tiny subset, `abl-<what>-4k` is an ablation on the 4,000-question subset, `tino-<model>` is a full-data model.

| File | Written when | Contents |
|---|---|---|
| `config.json` | start | the resolved config, overrides included |
| `provenance.json` | start | git commit and dirty state, library versions, chip, memory, start time |
| `data.json` | after data load | dataset repo, revision, file, SHA-256, record counts, rows skipped; for distillation, the teacher labels revision, temperature, alpha and coverage |
| `train_log.jsonl` | every `log_every` steps | loss, accuracy, gradient norm, learning rate, tokens per second, peak memory |
| `resources.jsonl` | every `log_every` steps | system free memory, swap, MLX active, cache and peak memory |
| `evals.jsonl` | every development evaluation | accuracy, log-loss, Brier, ECE, per-source accuracy, whether it is the best so far |
| `final.json` | end | best step, fitted temperature, every final split raw and calibrated, seconds per question, training minutes |
| `predictions/` | end | per-question logits and labels for each final split |
| `checkpoint.json` | end, then publish | local weights directory; after `publish.py`, the Hub repo and revision |
| `aborted.json` | on a guard abort or a manual stop | reason, step, resources at the time, whether a best checkpoint was kept |

Teacher-label runs write `final.json` with per-split teacher accuracy and the labels revision. Zero-shot evaluations write `final.json` with per-model, per-suite results and every prediction.

The training script commits and pushes the run directory at every evaluation, so a run that dies mid-way still leaves its record on GitHub.

## Adding an experiment

1. Add or copy a config in `configs/`, or use `--set key=value` overrides (JSON values are parsed).
2. Commit. `scripts/train.py` refuses to start from uncommitted code unless `--allow-dirty` is passed; smoke runs are exempt.
3. Run one job at a time, at low priority, with the Mac kept awake: `caffeinate -i nice -n 10 uv run python scripts/train.py --config configs/<name>.json`. For several jobs, add them to a queue script like `scripts/queue.sh`. Two GPU jobs at once will trip the memory guard.
4. Smoke-test first: `--smoke` runs the whole pipeline on 240 questions in about ten minutes.
5. For a released model, `scripts/publish.py --run runs/<id>` uploads the weights with a generated model card and records the Hub revision in the run.
6. Compare runs question by question with `scripts/report.py --pair <runA> <runB> --split transfer-v4/test` (McNemar test and a bootstrap interval).
7. Regenerate the index, registry and results file: `uv run python scripts/collect_results.py`, then commit them with the run.
8. Write the conclusion into `RESEARCH.md` next to the run links, and into `LESSONS.md` if it changes a lesson.

## Reading results honestly

- Selection uses the development split; test splits are read once per released model. Ablations report development splits only.
- Out of domain, the same recipe moved by up to 4.6 points between seeds. Treat any single-seed gap under about 4 points as unproven.
- A dev log-loss of exactly 1.478 means the model predicts every option equally; `collect_results.py` flags such runs as collapsed.
- Kev and Jev reference numbers come from Kev's model cards and harness. They are close, not exact, comparisons.

## Machine safety

`tino/guard.py` runs before every optimizer step and evaluation batch. It caps MLX memory at 10 GB, pauses when the Mac's free memory drops under 25%, and aborts the run (keeping the best checkpoint and pushing the record) under 12% free, if swap grows by more than 3 GB, or after 30 minutes paused. Every run's limits are in its `config.json` under `guard`.
